# KVLite Vector Core 重构执行步骤书

## 0. 执行目标

本轮重构目标不是把 KVLite 改造成 Faiss、hnswlib 或 USearch 的 wrapper，而是将 KVLite 向量模块拆成两层：

```text
KVmanager：
  负责 V 族命令、record 管理、key/scope、TTL、metadata、AOF/RDB、replication、rebuild 和 Agent 集成。

vector_core：
  负责向量计算，只提供两种索引：
    1. core/flat：精确检索，作为 ground truth 和 recall baseline。
    2. core/hnsw：近似检索，作为主生产索引。
```

核心原则：

```text
record store 是 source of truth。
flat / hnsw index 是 derived state。
index graph 不作为持久化事实来源。
启动或加载后可以从 record store rebuild index。
```

---

# 1. 总体阶段划分

本次落地分为三个阶段：

```text
Stage 1：边界重构，不改变行为。
Stage 2：实现 core/flat。
Stage 3：实现 core/hnsw。
```

不要一开始就做 HNSW。正确顺序是：

```text
先拆 manager/core 边界
再实现 exact_flat
最后实现 HNSW
```

原因是：如果不先切断 backend 与 manager 的耦合，后续 `core/flat` 和 `core/hnsw` 都会继承旧结构问题。

---

# 2. Stage 1：边界重构，不改变行为

## 2.1 阶段目标

Stage 1 只做边界拆分，不追求性能，不实现新索引，不改变 V 族命令行为。

目标是：

```text
index ops 只处理：
  record_id
  vector
  score

KVmanager 负责：
  question
  answer
  scope
  TTL
  metadata
  threshold
  response 组装
```

Stage 1 结束后，外部行为应保持不变：

```text
VSET / VSEARCH / VDEL / VINDEX / VINFO 结果保持兼容。
```

---

## 2.2 Step 1A：拆分头文件边界

当前 `include/kvs_vector.h` 职责过重，后续需要拆成 public API、manager、record、core、backend 几类。

建议新增：

```text
include/kvs_vector.h
include/kvs_vector_manager.h
include/kvs_vector_record.h
include/kvs_vector_core.h
include/kvs_vector_backend_faiss.h
include/kvs_vector_backend_hnswlib.h
```

职责划分：

```text
kvs_vector.h：
  只保留 public API，例如 kvs_vector_init / kvs_vector_set / kvs_vector_search / kvs_vector_info。

kvs_vector_manager.h：
  manager 内部接口，例如 prepare、commit、search resolve、rebuild orchestration。

kvs_vector_record.h：
  vector record、record store、key/scope map。

kvs_vector_core.h：
  index ops、hit、core info、metric、core lifecycle。

kvs_vector_backend_faiss.h：
  Faiss adapter ABI。

kvs_vector_backend_hnswlib.h：
  hnswlib adapter ABI。
```

本步骤不移动 `.c/.cpp` 文件，只拆头文件和 include 依赖。

验收命令：

```bash
make clean
make ENABLE_HNSWLIB=1 ENABLE_FAISS=1 -j"$(nproc)"
```

验收标准：

```text
1. 构建通过。
2. include/kvs_vector.h 不再继续暴露新的 internal 结构。
3. 旧 public API 仍可被外部使用。
4. 没有改变 V 族命令行为。
```

## 2.3 Step 1B：收窄统一 Index Ops

新增或调整 `kvs_vector_core.h` 中的统一 index ops。

目标接口：

```c
typedef struct kvs_vector_hit_s {
    uint64_t record_id;
    float score;
} kvs_vector_hit_t;

typedef struct kvs_vector_index_info_s {
    size_t capacity;
    size_t size;
    size_t dim;
    int metric;
    size_t memory_bytes;
    int ready;
    int needs_rebuild;
    size_t deleted_count;
} kvs_vector_index_info_t;

typedef struct kvs_vector_index_ops_s {
    int (*reserve)(void *index, size_t capacity);

    int (*add)(
        void *index,
        uint64_t record_id,
        const float *vector,
        size_t dim
    );

    int (*search)(
        void *index,
        const float *query,
        size_t dim,
        size_t topk,
        kvs_vector_hit_t *out,
        size_t *out_count
    );

    int (*mark_delete)(void *index, uint64_t record_id);
    int (*reset)(void *index);
    int (*info)(void *index, kvs_vector_index_info_t *out);
    void (*destroy)(void *index);
} kvs_vector_index_ops_t;
```

必须遵守：

```text
index ops 不接收 scope。
index ops 不接收 TTL。
index ops 不接收 threshold。
index ops 不返回 question。
index ops 不返回 answer。
index ops 不返回 scope。
index ops 不访问 metadata。
```

验收标准：

```text
1. index ops 入参只包含 record_id + vector。
2. index ops search 只返回 record_id + score。
3. 旧 search result 的组装迁移到 manager 层。
```

## 2.4 Step 1C：新增 manager 回表路径

新增 manager 搜索结果解析函数：

```c
int kvs_vector_manager_resolve_hits(
    const kvs_vector_hit_t *hits,
    size_t hit_count,
    const kvs_vector_search_params_t *params,
    kvs_vector_search_result_t *results,
    size_t *result_count
);
```

职责：

```text
1. record_id -> record。
2. 检查 record 是否 active。
3. 检查 record 是否 deleted。
4. 检查 TTL 是否过期。
5. 检查 scope 是否匹配。
6. 检查 threshold 是否满足。
7. 填充 question / answer / scope / score。
8. 截断 topK。
```

注意：为了避免 manager 过滤后结果不足，可以让 core search 返回 `topk * overfetch_factor` 的候选，例如：

```text
overfetch_factor = 2 或 4
```

验收标准：

```text
1. backend adapter 不再直接组装 kvs_vector_search_result_t。
2. manager 统一负责 search result response。
3. VSEARCH 外部返回结果不变。
```

## 2.5 Step 1D：backend label 从 record_index 切换为 record_id

当前旧结构中 backend label 使用 `record_index`，后续应统一改为稳定的 `record_id`。

目标：

```text
旧：
  backend label = record_index

新：
  backend label = record_id
```

改造范围：

```text
src/vector/kvs_vector_index.c
src/vector/kvs_vector_faiss_ops.c
src/vector/kvs_vector_hnswlib_ops.c
include/kvs_vector_faiss_backend.h
include/kvs_vector_hnswlib_backend.h
```

短期允许：

```text
manager 内部继续保留 record_index / slot。
```

但禁止：

```text
backend 对外使用 record_index 作为稳定 label。
```

验收标准：

```text
1. VSET 后 VSEARCH 可查。
2. VDEL 后 VSEARCH 不返回被删除记录。
3. RDB load 后 rebuild 仍可查。
4. Faiss/hnswlib adapter 返回 record_id + score。
```

---

## 2.6 Step 1E：移动过滤逻辑到 manager

将以下过滤逻辑从 backend adapter 中移出：

```text
scope filtering
deleted filtering
threshold filtering
TTL filtering，如果存在
metadata filtering，如果未来支持
```

backend 只负责返回候选：

```text
record_id + score
```

manager 再负责产品语义过滤。

验收标准：

```text
1. adapter 不访问 g_vector_state.store。
2. adapter 不读取 question / answer / scope。
3. adapter 不判断 record active/deleted。
4. adapter 不判断 scope。
5. VSEARCH 行为保持兼容。
```

## 3.4 Step 2C：实现 flat reserve/add/search/delete/info

执行顺序：

```text
1. create/init
2. reserve
3. add
4. search
5. mark_delete
6. reset
7. info
8. destroy
```

flat search 逻辑：

```text
for slot in [0, capacity):
  if slot deleted:
    continue

  score = distance(query, vectors + slot * dim)

  push into topK heap

export:
  record_id + score
```

注意：

```text
flat search 不回表。
flat search 不处理 scope。
flat search 不处理 TTL。
flat search 不处理 metadata。
```

# 4. Stage 3：实现 core/hnsw

## 4.1 阶段目标

实现 KVLite 自己的 USearch-inspired HNSW core。

目标不是第一版超过 USearch，而是从结构上消除明显低效点：

```text
1. search 热路径 malloc/free。
2. full memset visited。
3. vector<vector<int>> 图结构。
4. std::priority_queue 热路径。
5. manager 参与 graph search。
6. graph search 返回完整 record。
```

## 4.4 Step 3C：实现 search context pool

新增：

```c
kvs_hnsw_search_context_t *kvs_hnsw_context_acquire(...);
void kvs_hnsw_context_release(...);
```

context 包含：


要求：

```text

3. search 热路径不 malloc/free。
4. context buffer 在 reserve 或 context pool init 时分配。
```

visited 机制：


```text

```

验收标准：

```text
1. search context 可复用。
2. visited 不依赖每次 memset。
3. heap buffer 不在 search 中动态分配。
```

## 4.7 Step 3F：实现 HNSW add

执行顺序：

```text
1. 获取或分配 slot。
2. 写入 vectors[slot * dim]。
3. 写 slot_to_record_id。
4. 写 record_id_to_slot。
5. 生成 random level。
6. 如果是第一个点，设置 entry_point / max_level。
7. 从 max_level 到新节点 level 以上做 greedy search。
8. 在每一层搜索候选邻居。
9. 执行 neighbor selection。
10. 写入双向边。
11. 更新 entry_point / max_level。
```

第一版可以先实现简单 neighbor selection：

```text
按距离排序，选择前 M / M0 个。
```

后续再优化启发式选择。

验收标准：

```text
1. 多个节点可成功 add。
2. graph 中 level0 邻接关系正确。
3. size 正确增长。
4. duplicate record_id 可更新或返回明确错误。
```

---

## 4.8 Step 3G：实现 HNSW search

搜索流程：

```text
1. acquire search context。
2. 从 entry_point 开始。
3. 高层 greedy search。
4. level0 使用 ef_search 搜索。
5. 维护 candidate_heap 和 top_heap。
6. 导出 record_id + score。
7. release search context。
```

硬约束：

```text
1. search 内不 malloc/free。
2. search 内不访问 manager。
3. search 内不返回 question/answer/scope。
4. search 内不做 TTL/scope/metadata filtering。
```

验收标准：

```text
1. search 可以返回 topK record_id + score。
2. manager 可回表生成 VSEARCH 结果。
3. search 热路径无明显动态分配。
4. recall@10 可对比 core_flat。
```

---

## 4.9 Step 3H：实现 mark_delete 和 rebuild

第一版 delete：

```text
mark_delete(record_id):
  1. record_id -> slot
  2. deleted_flags[slot] = 1
```

不做：

```text
physical compact
slot relocation
graph edge rewrite
online compaction
```

rebuild：

```text
1. manager reset core_hnsw。
2. manager 遍历 record store。
3. 跳过 deleted / expired / invalid embedding。
4. 对每条 active record 调用 core_hnsw.add(record_id, embedding)。
```

验收标准：

```text
1. VDEL 后不返回删除记录。
2. VINDEX rebuild 后结果可查。
3. RDB load 后可 rebuild。
4. graph 不作为 source of truth。
```

# 7. 风险控制

## 7.1 过滤迁移风险

从 adapter 迁移过滤到 manager 后，可能出现候选不足。

解决：

```text
core search 返回 topK * overfetch_factor。
manager 过滤后再截断 topK。
```

建议：

```text
overfetch_factor = 4
```

---

## 7.2 record_id 迁移风险

从 `record_index` 切换为 `record_id` 后，可能影响：

```text
RDB load
rebuild
VDEL
backend adapter
free slot reuse
```

解决：

```text
保留 manager 内部 record_index。
core/backend 对外统一 record_id。
```

---

## 7.3 HNSW 实现风险

HNSW 不要一开始追求极致性能。

第一版优先级：

```text
正确性 > 可观测性 > 可 rebuild > 性能优化
```

但结构上必须避免：

```text
search malloc/free
full memset visited
manager 回调
返回完整 record
```

---

## 7.4 持久化风险

禁止把 HNSW graph snapshot 当作事实来源。

正确方式：

```text
RDB/AOF 保存 record。
启动后 rebuild flat/hnsw。
```

# 8. 最终验收清单

当所有阶段完成后，应满足：

```text
1. KVmanager / vector_core 边界清晰。
2. include/kvs_vector.h 只保留 public API。
3. index ops 只处理 record_id + vector / record_id + score。
4. backend adapter 不访问 g_vector_state.store。
5. backend label 使用 record_id。
6. core_flat 可用，并作为 recall baseline。
7. core_hnsw 可用，并参考 USearch 的 slot / reserve / context / visited tag / compact graph 思路。
8. VSET/VSEARCH/VDEL/VINDEX/VINFO 行为兼容。
9. RDB load 后可 rebuild。
10. AOF rewrite/replay 仍可用。
11. VINFO 能区分 manager stats 和 core stats。
12. benchmark 能输出 core_flat、core_hnsw、hnswlib、Faiss 对照。
```
